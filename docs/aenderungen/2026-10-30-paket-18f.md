# Änderungsnotiz — Paket 18F: Betrieb unter Last

Stand 2026-10-30 · Basis Paket 18E-2 (PR #34) · Plan
[`docs/plans/2026-10-30-paket-18ef.md`](../plans/2026-10-30-paket-18ef.md), Phase 3

**Warum:** Der Störtest zeigte drei Lücken unter Last und bei Störungen. Ein abgelehnter
LLM-Schlüssel (401) stand nur als Fehlertext an der Fehlerstelle im Log. Das Warten auf einen
LLM-Platz hatte keine Frist — ein hängender Anbieter füllte eine Kopie, und Klassifikator und
Antwort warteten nacheinander. Das äußere Ratenlimit (20 je Minute und IP) war hinter einem
Schul-NAT zu knapp, und ein 429 sah im Widget aus wie ein allgemeiner Fehler.

| Was | Wie |
|---|---|
| Abgelehnter Schlüssel (3.1) | Die Engstelle `services/llm_parallel.platz` sieht jeden LLM-Aufruf (Chat, Einbettung, Klassifikator, Strom — `llm.semaphore()` ist jetzt ein Platz). Eine 401, auch verkettet oder von instructor verpackt, ergibt eine Zeile `llm_schluessel_abgelehnt anbieter=… route=… quelle=…`, höchstens einmal je Minute mit der Zahl der ausgelassenen: ERROR beim eigenen Schlüssel (`b_api_key`, `openai_api_key`), WARNING beim vom Proxy weitergereichten. Nie der Schlüssel, nie der Text des Anbieters. Zähler `boerdi_llm_schluessel_abgelehnt_total{anbieter,quelle}`, Alarmregel `BoerdiLlmSchluesselAbgelehnt` |
| Frist beim LLM-Platz (3.2, Nutzer-Entscheid F2) | `LLM_SLOT_WAIT_S` (Vorgabe 30, 0 = ohne): wartet ein Chat-Aufruf länger, gilt der Zug als ausgelastet, und jeder weitere Aufruf desselben Zugs scheitert sofort (ein Merker je Zug, gebunden vor dem Graphen). Andere Züge warten normal; Hintergrund und Import ohne Frist. Zähler `boerdi_llm_platz_frist_total`, Alarmregel `BoerdiLlmAusgelastet` |
| „Ausgelastet“-Blase (3.3) | Ein ausgelasteter Zug antwortet „Gerade sind sehr viele Anfragen gleichzeitig unterwegs … in einer Minute noch einmal“ (de/en) mit „Nochmal versuchen“ — ohne Fehlernummer, denn es ist Last, kein Fehler. Muster-Weg, Werkzeugschleife und Agent-Weg wählen den Satz an einer Stelle (`services/fehlertext`) |
| Ratenlimit (3.4) | Vorgabe `120/minute`. Ein ungültiger `RATE_LIMIT_CHAT` verhindert den Start mit klarer Meldung (bisher scheiterte slowapi je Anfrage, das Limit war faktisch aus); die Aus-Wörter (`off`, `0`, `none`, `false`, `disabled`) bleiben |
| 429 im Widget (3.5, Nutzer-Entscheid F3) | Strom, POST und Verlauf lesen `Retry-After` an einer Stelle (`ui/src/stream/http-fehler`). Ein 429 ergibt „Gerade kommen sehr viele Anfragen aus deinem Netz an …“ — mit der Wartezeit in Sekunden, wenn sie mitkommt —, kein zweiter Versand, und die getippte Frage steht wieder im Eingabefeld (wie bei „beschäftigt“). Sammlungs-Aktionen ebenso |

## Was sich im Betrieb ändert

| Was | Muss | Kann |
|---|---|---|
| Image | neu bauen und ausrollen (Backend und Widget); keine Migration | |
| `RATE_LIMIT_CHAT` | **vor dem Update prüfen:** ein ungültiger Wert (etwa `120/min`) verhindert jetzt den Start. Leer = neue Vorgabe 120/minute | einen eigenen Wert setzen; hinter einem Proxy ohne `TRUST_FORWARDED_FOR` teilen sich weiter alle eine IP |
| `LLM_SLOT_WAIT_S` | | Vorgabe 30 s; 0 schaltet die Frist ab |
| Monitoring | | Zähler und die zwei Alarmregeln aus `deploy/helm/values.example.yaml` übernehmen |
| Log | | neue Zeilen `llm_schluessel_abgelehnt …` (ERROR/WARNING) und `llm_platz_frist …` (WARNING), je höchstens einmal je Minute |

## Prüfung

- Backend: neu `test_llm_engstelle.py` (401-Meldung je Quelle, Drossel, verpackte und verkettete
  401, Frist, Zug-Merker, andere Züge, Frist 0, Hintergrund ohne Frist) und
  `test_ausgelastet_blase.py` (Satz, Agent-Weg, Merker über Task-Grenzen); Werkzeugschleife,
  Schnellantworten, Einstellungen (Ratenlimit gültig/ungültig/aus). Zwei Tests lasen
  `llm.semaphore()` als Semaphor — jetzt den Anbieter-Deckel darunter.
- Widget: Spec für `http-fehler`, Strom und POST mit `Retry-After`, Senden (Strom- und POST-429,
  Frage zurück ins Feld), Sammlungs-Aktionen; E2E: ein 429 auf den Strom zeigt die Wartezeit.
