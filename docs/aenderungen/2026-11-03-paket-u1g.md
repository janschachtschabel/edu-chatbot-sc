# Änderungsnotiz — Paket U1-g: UI-Module in der Evaluation

Stand 2026-11-03 · Basis: U1-f (`docs/aenderungen/2026-11-03-paket-u1f.md`) · Plan
[`docs/plans/2026-11-02-paket-u1-ui-module.md`](../plans/2026-11-02-paket-u1-ui-module.md) §17

**Warum:** Keine Evaluation meldete `environment.ui_module` — in Gold- und generativen Läufen bot
der Agent also nie Auswahlfeld oder Themenbaum an, und kein Check sah die gezeigten Blöcke. Ein
Zug konnte nicht im Auswahlfeld antworten. Nutzer-Auftrag: Beispiel-Abläufe im Bildungskontext
(Themenbaum Physik, Gespräch, das auf eine Entscheidung hinausläuft, …).

| Teil | Was |
|---|---|
| Meldung (G-1/G-2) | Gold-Lauf (Studio und Kommandozeile) und generativer Lauf melden alle Katalog-Module wie das Widget (`ui_module/katalog.widget_module`, CLI: `manifeste.json`). Schalter `ui_module: bool = true` an `StartRequest`/`GoldenRunRequest`, Studio-Haken „UI-Module melden wie das Widget“ in beiden Start-Formularen, CLI `--ohne-ui-module`. Ein `ui_module` im `environment` eines Flows gewinnt. Liste in `config.ui_module`, in den Messbedingungen (`ui_module`, Studio-Zeile „UI-Module“, Markdown-Bericht) und im Bedingungsvergleich (`engine_metrics.conditions_of`) |
| Check `ui` (G-3) | `ui_any`/`ui_none` gegen `ui.ui_bloecke[].modul` — der gezeigte Block ist die Grundwahrheit, nicht `tools_called` (bleibt MCP plus Module mit Datenquelle). Harte Kategorie `ui` (Scorecard „UI-Module“). Namen beim Laden gegen den Katalog geprüft, vor dem ersten bezahlten Zug |
| Antwort im Auswahlfeld (G-4) | Zug-Schlüssel `ui_antwort: {waehle: [Wendung …], freitext?}`: Wahl über die Beschriftung des offenen `ui_entscheidung`-Blocks im vorigen Zug, Nachricht wie im Widget; ohne Frage/Treffer geht `message` getippt. `observed.ui_antwort.status` |
| Sichtbar für Judge und simulierte Person (G-5) | Textfassung jedes Blocks außer Inhaltsrahmen und Trefferliste im Judge-Text (`augment_bot_text`, Zwilling `runner._augment_bot_text`) und im Text an die simulierte Person; die antwortet getippt — kein neuer LLM-Aufruf |
| Modul-Nutzung (G-6) | Jeder Zug-Datensatz trägt `ui_module`. `GET /api/eval/runs/{id}` liefert `modul_nutzung` (beim Lesen, `services/eval/modul_nutzung.py`): je Muster (Agent = `AGENT`) und je Anwendungsfall die Züge je Modul; alte Läufe „nicht erfasst“. Studio: Tabelle „Modul-Nutzung“ im Lauf-Detail (`eval-modul-nutzung.component`), Markdown-Bericht: Abschnitt „Modul-Nutzung“ |
| Beispiel-Abläufe (G-7) | `evals/ui-module-flows.yaml`, sieben Flows `GV-UI-1` … `GV-UI-7` (eigene Datei, nicht in der Seed-Suite), Format-Wächter `tests/test_golden_ui_module_flows.py` |

## Review

Vierzehn Befunde (Plan §17, „Review-Befunde U1-g“), je am Code geprüft, roter Test zuerst, alle
bestätigt und behoben:

| Teil | Was |
|---|---|
| Wahl im Auswahlfeld (#1, #2) | `baue_ui_antwort` trifft in drei Stufen — genaue Beschriftung/Kennung, ganze Wörter, Wortteil als letzter Rückfall; je Wendung zählt nur ihre beste Stufe („Physik“ wählt nicht mehr „Astrophysik“, Mehrfachwahl nimmt keine bloßen Wortteil-Treffer mehr mit). GV-UI-5: Wendungen nach Absicht, ohne „Grundlagen“ und „6.“ |
| Status und Freitext (#3) | `observed.ui_antwort.status` heißt `gesendet` statt `beantwortet` — ob der Server die Wahl annahm, zeigt seine Antwort nicht. Freitext auf 1000 Zeichen gekürzt wie im Widget (`freitext_gekuerzt`, Warnzeile). Annahme sichtbar machen hieße ein neues Debug-Feld: nicht umgesetzt |
| Generativer Dialog (#4) | Die Dialog-Stufe gibt Judge und simulierter Person denselben Text wie die Szenario-Stufe (Karten, Dokumente, Leinwand, Textfassungen); die Person liest die übrige Antwort bis 1500 Zeichen und die Textfassungen danach — die Frage wird nicht mehr abgeschnitten |
| Beispiel-Abläufe (#5, #6) | GV-UI-1 Zug 2 lässt auch die Trefferliste gelten (die Quittung des Baums nennt keine Knoten; Grenze dokumentiert); GV-UI-6 Zug 1 verbietet nur den Baum |
| Messbedingungen (#7) | `ui_module_wirksam` (gemeldet und aktiv laut Studio-Schaltern, dazu `agent_aus`), auch im Bedingungsvergleich; `gold_flows.eigene_ui_module` bei Flows mit eigenem `ui_module`; Studio-Hinweis: abgeschaltete Module bietet der Server trotzdem nicht an |
| A/B-Vergleich (#8) | `compare_golden.py` nennt die gemeldeten UI-Module beider Berichte und warnt bei Ungleichheit |
| Studio (#9, #10) | Geöffneter Gold-Zug: UI-Soll, gezeigte Module, Antwort im Auswahlfeld (de/en). Modul-Nutzung und Bericht: „Noch keine beantworteten Züge.“ statt „Lauf von vor U1-g“ bei null Zügen |
| Kleinigkeiten (#11–#14) | Ersatzblasen zählen nicht in der Modul-Nutzung; Format-Wächter wählt Flows über die Kennung; Zwillings-Test `_SCHON_GEZEIGT`/`_TEXTFASSUNG_MAX`; keine „never awaited“-Warnungen mehr in `test_eval_ui_module.py` |

Im Betrieb: kein neues Feld an der API, keine Migration. Berichte und Messbedingungen tragen drei
neue Schlüssel (`freitext_gekuerzt`, `ui_module_wirksam`, `gold_flows.eigene_ui_module`), der
A/B-Bericht zwei (`ui_module_ref`/`ui_module_new`). Wer `observed.ui_antwort.status ==
"beantwortet"` auswertet, liest jetzt `gesendet`.
