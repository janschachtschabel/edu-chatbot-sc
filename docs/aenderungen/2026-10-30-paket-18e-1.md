# Änderungsnotiz — Paket 18E-1: still geschluckte Ausnahmen, die echten Risiken

Stand 2026-10-30 · Basis `main` `4f5c914` (Paket 18C/D komplett) · Plan
[`docs/plans/2026-10-30-paket-18ef.md`](../plans/2026-10-30-paket-18ef.md), Phase 1

**Warum:** Eine Neuaufnahme am Code fand 133 Fänge ohne Log und ohne Weiterwurf. Die meisten
schweigen zu Recht; sieben verändern Sicherheit, Datenschutz oder Korrektheit, und dazu kam ein
Datenschutzfehler ganz ohne Ausnahme: Ein im Rohtext-Editor gequotetes `messages: "false"` passierte
die Prüfung beim Speichern als „aus“, der Lader las es mit `bool("false")` als „an“ — Nachrichten
wurden trotz „aus“ gespeichert.

| Was | Wie |
|---|---|
| Abbruch kommt an, mit Frist (C1) | `obs/tasks.cancel_and_drain(…, frist_s=5)` wartet über `asyncio.wait`: ein Abbruch des Aufrufers kommt bei ihm an (bisher verschluckt: legte der Client auf oder fuhr der Server herunter, rechnete der Zug weiter), eine Aufgabe, die den Abbruch ignoriert, hält höchstens die Frist auf (Warnung). Ersetzt die Kopien in `respond`, `sse._aufgelegt`, `cancel_run_task`, Sitzungssperre (Freigabe läuft trotzdem), Herzschlag und Konfigurations-Listener; doppelte Aufgaben zählen einmal, auf DEBUG steht nur der Typ einer Ausnahme |
| Schalter wie das Gate lesen (N1) | neu `config_loader/schalter.als_schalter` — dieselbe Regel wie die Prüfung beim Speichern (`TypeAdapter(bool)`: `"false"`, `"no"`, `"0"`, `"off"` heißen aus); 14 Stellen in den Ladern, `rate_limits` (Block und Fenster), MCP-Server, Qualitätsprotokoll. Ein unbrauchbarer Wert ergibt die Vorgabe und eine Warnung je Schalter; ein Wächtertest hält `bool(…)` aus den Ladern fern. **Dazu für alle übrigen Leser:** der Konfigurations-Cache liest jedes Feld, das das Bereichsmodell als Schalter führt, mit derselben Regel (`domain/config_models/schalter`) — etwa `log_all_turns`, die Sicherheitsstufen, abgeschaltete Fremdserver; die Datenbank bleibt, wie gespeichert |
| Datenschutz fail-closed (C5, Nutzer-Entscheid F1) | ist die Datenschutz-Konfiguration nicht lesbar oder ein Schalter unbrauchbar (auch ein gespeichertes `null`), werden Nachrichten, Gedächtnis und Qualitätsprotokoll **nicht** gespeichert (bisher: doch, mit einer DEBUG-Zeile); Warnung höchstens je Minute; `GET /api/config/privacy` sagt dann, was zu korrigieren ist (409 statt 500) |
| Ratenlimit-Fenster (C2) | ein ungültiger Wert schaltet das Fenster weiter ab, jetzt mit einer Warnung je Fenster (Typ, nie der Wert) |
| Policy-Regeln (C3) | ein ungültiges Muster meldet sich einmal je Regel mit ihrer ID (bisher fiel die Regel still weg, auch ein Pflicht-Hinweis oder eine Werkzeugsperre); Muster werden nur einmal übersetzt statt je Zug |
| Frontmatter streng (C4) | beim Speichern im Rohtext-Editor und beim Wiederherstellen einer Sicherung wird ein kaputter Kopf (ungültiges YAML, keine Zuordnung, kein schließendes `---`) abgewiesen — 400 bzw. „Sicherung ungültig“ — statt still zu `{}` zu werden; das Kopfende zählt nur in Spalte 0 (ein Wert mit einer Zeile `---` bleibt gültig); der Seed-Import bleibt tolerant |
| Frist bleibt beim Schalter-PUT (Review) | `PUT /api/config/privacy` ersetzt nur noch die vier Schalter und lässt den Rest des Bereichs stehen — bisher fiel eine im Studio gesetzte Frist (`retention_days`) dabei still auf 30 zurück, und der nächste Aufbewahrungslauf hätte ältere Verläufe gelöscht; das Studio selbst nutzt diese Route nicht |
| Sitzungs-ID (N3) | ohne starke Zufallsquelle wirft `generateSessionId`, statt auf `Math.random` zurückzufallen |
| Gedrosselte Zeilen | neu `obs/drossel.gedrosselt` — höchstens eine Zeile je Schlüssel und Abstand, mit Zahl der ausgelassenen |
