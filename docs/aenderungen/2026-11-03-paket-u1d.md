# Änderungsnotiz — Paket U1-d: Entscheidung als erstes abfragendes UI-Modul (U1-d1, U1-d2)

Stand 2026-11-03 · Basis: U1-c (`docs/aenderungen/2026-11-02-paket-u1c.md`) · Plan
[`docs/plans/2026-11-02-paket-u1-ui-module.md`](../plans/2026-11-02-paket-u1-ui-module.md) §14

**Warum:** Bisher zeigten UI-Module nur an. Mit `ui_entscheidung` kann die KI im Agent-Modus eine
Rückfrage mit festen Möglichkeiten stellen; die Person klickt statt zu tippen, und die Antwort
kommt geprüft im nächsten Zug an. Dazu kommt die in U1-b1 verschobene Durchsetzung der
Fähigkeiten: Jeder Block bekommt einen eigenen Host. U1-d2 bringt dasselbe in den Muster-Modus
(U-F4: nur Module, die das Muster in `tools:` nennt) und ins Studio.

| Teil | Was |
|---|---|
| Modul | `ui_entscheidung` (abfragend, `agent: true`): Frage, 2–8 Möglichkeiten mit Kennung, Beschriftung und Hinweis, Einzel- oder Mehrfachwahl, optional Freitext (≤ 1000). Native Radio/Checkbox in `fieldset`/`legend`, „Antworten“ gesperrt ohne Wahl und während eines Zugs, danach nur lesend mit der Antwort; de/en |
| Modul-Werkzeuge allgemein | Jedes Katalog-Modul mit `agent: true` (außer Inhaltsrahmen und abgeleiteten) ist ein Werkzeug der Agent-Schleife; der Aufruf wird gegen `eingabe` geprüft (Kennungen eindeutig), ein Fehler geht an die KI zurück. Ein abfragender Block beendet die Runde (`stop_reason` „frage“), ohne Prosa steht ein fester Satz („Bitte wähle unten aus.“), darunter keine Schnellantworten |
| Antwortweg | `ChatRequest.ui_antwort {block_id, daten}`, `message` = lesbare Fassung. Geprüft im ersten Knoten gegen die offene Frage der Sitzung (`entities._offene_frage`); ungültig → verworfen, der Text zählt wie getippt. Jeder Vordergrund-Zug schließt die Frage, ein Hintergrund-Zug nicht. Eine Modul-Antwort zählt bei offener Schreib-Abnahme als NEIN |
| Folgezug | Die geprüfte Antwort steht gerahmt vor der Nachricht an die KI (Frage, gewählte Beschriftungen samt Kennung, Ergänzung) und im Debug-Block der Nutzernachricht (`_ui_antwort`) |
| Verlauf | Abfragende Blöcke tragen `beantwortet` (samt `antwort`), `veraltet` oder `offen` — abgeleitet aus den späteren Nutzernachrichten |
| Widget | Host je Block (Kennung, nur die Fähigkeiten aus dem Manifest, sonst Warnung); `antworten()` sendet den nächsten Zug mit `ui_antwort`; der Block wird sofort `beantwortet`, jede andere offene Frage mit dem nächsten Zug der Person `veraltet` |
| U1-d2 Muster-Modus | Ein Muster darf Modul-Werkzeuge (`agent: true`) in `tools:` nennen; angeboten nur, wenn das Widget das Modul meldet. `phase3_modulate` trennt sie von den MCP-Werkzeugen (`ui_werkzeuge`) — sie zählen nicht als Pflichtwerkzeug (keine „KORREKTUR“-Runde) und nicht als Kuratier-Absicht. In der Muster-Schleife eine Vorrunde wie für Dokumente; eine Frage beendet die Runde (vor der A1-Reflexion), darunter keine Schnellantworten, ohne Text der feste Satz. Der Folgezug bekommt die geprüfte Antwort bzw. die Frage gerahmt vor die Nachricht — wie im Agent-Modus |
| U1-d2 Studio | Muster-Formular: Feld `tools` schlägt `ui_entscheidung` vor. Agent-Werkzeuge: Zeile `ui_entscheidung` (eingebaut, „Nur wenn das Widget das Modul meldet …“). Prompt-Vorschau: eigene Zeile für die Modul-Werkzeuge (nicht mitgezählt). Agent-Spur: Ende-Grund „frage“ beschriftet (de/en) |

## Was sich im Betrieb ändert

| Was | Muss | Kann |
|---|---|---|
| Image | Backend und Studio neu bauen, mit neuem Widget-Bündel; keine Migration, keine neue Umgebungsvariable | |
| Widget | Eingebettete Kopien neu ausliefern (auch die Kopie im Chrome-Plugin). **Seit dem Review bekommt nur ein Widget, das seine Module meldet (`environment.ui_module`), Modul-Werkzeuge** — ältere Widgets (auch U1-a bis U1-c), Gastanwendungen mit eigenem Client und der Studio-Probelauf bekommen keine, die KI fragt dort in Prosa. Die Studio-Widget-Vorschau lädt das echte Bündel und meldet sie | |
| API | | `ChatRequest.ui_antwort` (optional, Schema `UiAntwort`); `Environment.ui_module` (optional, ≤ 50 Namen); neuer `stop_reason`/`result_stop_reason` „frage“ (kein Fehler, kein `result`); im Verlauf haben abfragende Blöcke jetzt `beantwortet`/`veraltet` |
| Agent-Modus | | Die KI sieht das Werkzeug `ui_entscheidung`; Master-Skill oder Rollen-Vorgabe können beschreiben, wann sie es nutzen soll (die Werkzeugbeschreibung kommt aus dem Manifest) |
| Muster-Modus (U1-d2) | | **Muster können jetzt Modul-Werkzeuge unter `tools:` nennen** (Studio → Muster, Feld „tools“, z. B. `ui_entscheidung` in einem Rückfrage-Muster). Ohne Eintrag ändert sich nichts — kein Seed nennt eines. Wirkt nur mit einem Widget, das seine Module meldet; ohne `mcp` in `sources` steht weiter die Regel „Rufe KEINE Tools auf“ im Prompt, dort also nicht sinnvoll. Keine Migration, kein Vertragswechsel |
| Bündel | | 597,86 kB roh / 174,96 kB gzip nach dem Review (vorher 589,12 / 172,77) |

## Reviews

**Review U1-d1 (2026-11-03)** — acht Befunde, alle behoben (Tests zuerst):

| # | Befund | Behoben |
|---|---|---|
| 1 | Freitext der Antwort umging die Sicherheitsprüfung | Regex-Tor, `assess_safety` und Rückfall lesen Nachricht und Ergänzung, durch einen Zeilenumbruch getrennt (`antwort.sicherheits_text`) |
| 2 | Eine verworfene Modul-Antwort mit „Ja“ galt als Zustimmung zur offenen Schreib-Abnahme | `setup` merkt sich, dass eine Antwort kam; `discard_stale_approval(modul_antwort=…)` wertet sie als NEIN |
| 3 | Ohne Klick im Auswahlfeld kannte der Folgezug weder Frage noch Möglichkeiten | `ctx.geschlossene_frage`; ohne geprüfte Antwort steht `[DEINE LETZTE FRAGE …]` mit nummerierten Möglichkeiten vor der Nachricht |
| 4 | `stop_reason` „frage“ fehlte in der Doku für Gastgeber | Tabellen in `browser-plugin-einbindung.md` und `agent-modus.md`, Beispiel behandelt es wie `text` |
| 5 | Endmarke `[ENDE ANTWORT]` nur wörtlich ersetzt | `ANTWORT`/`FRAGE` in `domain/endmarken._MARKEN`; beide Blöcke laufen durch `entschaerfe_endmarken` |
| 6 | Doppelte id bei Möglichkeit `freitext` | Namensräume `opt-<id>` und `eingabe-freitext` |
| 7 | Block blieb nach gescheitertem Zug lokal `beantwortet` | `runSendMessage` meldet, ob der Server den Zug annahm (`connected` oder Antwort); sonst `wiederOffen` |
| 8 | Modul-Werkzeuge auch für Widgets, die sie nicht zeigen können | `Environment.ui_module`; das Widget meldet die Namen seines Registers, das Backend bietet nur diese an |

**Review U1-d2 (2026-11-03)** — zwölf Befunde, alle behoben (Tests zuerst, `tests/test_ui_entscheidung_muster_review.py`):

| # | Befund | Behoben |
|---|---|---|
| 1 | Ein Modul-Werkzeug allein erzwang in der ersten Runde einen Werkzeugaufruf (`tool_choice="required"`) — ein Rückfrage-Muster ohne Antwort-Werkzeug zwang die KI in die Auswahl-Frage | Erzwungen wird nur, wenn ein Werkzeug außer den Modulen angeboten ist; `respond_to_user`/`select_top_cards`/Inhaltsrahmen zählen weiter (Verhalten vor U1-d2) |
| 2 | Der Klassifikator sah nach einer Auswahl-Frage nur „Klasse 5“ | Derselbe gerahmte Block wie für die KI (Antwort oder übergangene Frage) steht vor der Nachricht an den Klassifikator; Cache-Präfix unverändert |
| 3 | Werkzeug-Treue der Auswertung zählte Module als Pflicht | Nur MCP-Namen; ein Muster nur mit Modulen zählt nicht |
| 4 | Seed-Wächter kannte nur MCP-Kataloge | Modul-Werkzeuge erlaubt; Inhaltsrahmen und abgeleitete Module in `tools:` werden abgewiesen — auch im Studio (Validator `PatternFrontmatter.tools`) |
| 5 | Fehlerweg von `respond` ungetestet | Test: keine Blöcke, keine offene Frage, Schnellantwort-Modus unverändert |
| 6 | Studio-Hinweis `tools` nannte nur WLO-Werkzeuge | Ein Satz de/en zu den Bedingungen der UI-Module |
| 7 | README `ui-entscheidung` veraltet | U-F4-Regel |
| 8 | `crisis_blocked_tools` schlug `ui_entscheidung` vor | Eigener Katalog `mcp_tools` (nur MCP-Werkzeuge) |
| 9 | Eine Runde mit Auswahl-Frage buchte als `tool_loop` | Bucht als `response` wie `respond_to_user` |
| 10 | Kommentar zu `tools` veraltet | Nennt die UI-Module |
| 11 | Schlüssel `_ui_bloecke` doppelt belegt | `_modul_bloecke_zug` im `session_state` |
| 12 | Pflichtwerkzeug-Test fast tautologisch | Gerufene Werkzeuge ohne Modul, nicht aus der Ausgabe |

Im Betrieb: `GET /api/config/choices` liefert zusätzlich den Katalog `mcp_tools`; ein Muster mit `ui_linkbox`, `ui_trefferliste` oder `ui_inhaltsrahmen` in `tools:` lässt sich nicht mehr speichern (kein Seed nennt eines). Keine Migration, Vertrag unverändert.
