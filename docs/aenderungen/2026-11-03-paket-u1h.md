# Änderungsnotiz — Paket U1-h: Unterthemen im selben Baum aufklappen

Stand 2026-11-03 · Basis: U1-g (`docs/aenderungen/2026-11-03-paket-u1g.md`) · Plan
[`docs/plans/2026-11-02-paket-u1-ui-module.md`](../plans/2026-11-02-paket-u1-ui-module.md) §18

**Warum:** Rückmeldung nach dem Test des Themenbaums: „schade das wir nachgeladenes unten drunter
anzeigen müssen“. Bisher öffnete „Unterthemen öffnen“ einen **neuen** Baum als neue Antwort
(Direktaktion `show_collection_tree`, ein Zug). Jetzt lädt das Aufklappen eines Knotens, dessen
Unterthemen noch fehlen, sie **ohne Zug und ohne KI** nach und hängt sie in **denselben** Baum —
wie „mehr laden“ die Trefferliste im selben Block ergänzt.

## Offen

- **Nachgeladenes gilt bis zum Neuladen.** Der Verlauf zeigt den ursprünglichen Baum; wer die Seite
  neu lädt, klappt erneut auf (der Werkzeug-Cache, 1800 s, macht das billig). Speichern hieße die
  gespeicherte Nachricht ohne Zug ändern (Schreibweg, Größe, Prüfung gegen `eingabe`, das nur eine
  Ebene Kinder kennt) — eigener Schritt, Entscheid Nutzer.
- **Unbekannte Unterthemen:** Knoten der zweiten Ebene eines Abrufs tragen einen Pfeil, auch wenn sie
  keine Unterthemen haben (der Server sagt es erst beim nächsten Abruf); danach werden sie ein Blatt
  mit „keine Unterthemen“.
- **Sitzung weg:** Löscht die Aufbewahrung eine Sitzung, während der Baum offen ist, antwortet der
  Endpunkt 404 — der Knoten zeigt „nicht geladen“ (ein neuer Zug legt die Sitzung wieder an).
- **Gold-Züge** können einen Knoten weiter nur getippt öffnen (U1-g, Offen); das Nachladen ist kein
  Zug und in der Evaluation nicht messbar.
- **Nach dem Review:** dasselbe Thema an zwei nicht verwandten Stellen teilt Auf/Zu; lange Titel
  brechen unter den Pfeil (seit U1-e); 404/422 bieten „Erneut laden“ weiter an — Plan §18, „Offen“.
