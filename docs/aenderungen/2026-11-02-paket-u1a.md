# Änderungsnotiz — Paket U1-a: Vertrag und Transport der UI-Module

Stand 2026-11-02 · Basis main `4e261c7` (Paket 20) · Plan
[`docs/plans/2026-11-02-paket-u1-ui-module.md`](../plans/2026-11-02-paket-u1-ui-module.md) §9, §10

**Warum:** Der Chatbot soll kleine Oberflächen (Inhaltsrahmen, Trefferliste, Linkbox,
Entscheidung, Themenbaum) wie Werkzeuge nutzen. Sie sollen getrennt entwickelbar sein und
gleich aussehen wie das Widget. U1-a legt dafür den Unterbau: wie ein Modul beschrieben wird,
wie ein Block mit der Antwort reist und wie das Widget ihn zeigt. Ein fertiges Modul enthält
U1-a noch nicht; das erste folgt mit U1-b (Inhaltsrahmen).

| Bereich | Was |
|---|---|
| Antwort | `ui.ui_bloecke`: Liste von Blöcken (`block_id`, `modul`, `version`, `art`, `daten`, `text`, `status`, `antwort`). Je Antwort höchstens fünf, höchstens einer offen abfragend; Daten über ~256 KB oder nicht als JSON darstellbar fallen mit Warnung weg |
| Speichern | im Debug-Block der Nachricht unter `_ui_bloecke` (wie die Dokument-Boxen); live und im Verlauf öffentlich an `ui` |
| Katalog | `boerdi/ui_module/katalog.py` prüft jedes Manifest gegen `manifest.schema.json`, `eingabe`/`antwort` als JSON Schema, `textfassung.feld` und alle Beispiele |
| Frontend | neue Bibliothek `projects/ui-module` (Vertrag, Register, Entwickler-README); Platzhalter `<boerdi-ui-bloecke>` in der Chat-Shell zeigt das Modul oder — fehlt es oder passt die Version nicht — die Textfassung |
| Werkzeuge | `npm run module:neu -- <name> [--abfragen]` legt ein Modul-Gerüst an; `npm run module:register` erzeugt Register und Backend-Katalog; CI prüft, dass beides aktuell ist |
| Budget | Widget-Bündel bis 690 kB roh / 200 kB gzip, Warnung ab 190 kB (Entscheid U-F2); gemessen 579,33 kB roh / 169,59 kB gzip |
| Lint | Module dürfen weder die Chat-Shell noch den Sammel-Export `@boerdi/ui` importieren |
