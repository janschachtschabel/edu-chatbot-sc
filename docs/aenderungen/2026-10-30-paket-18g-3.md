# Änderungsnotiz — Paket 18G-3: Robustheit

Stand 2026-10-30 · Basis Paket 18G-2 · Plan
[`docs/plans/2026-10-30-paket-18g.md`](../plans/2026-10-30-paket-18g.md)

**Warum:** Das Gesamt-Review fand Stellen, die unter Störungen falsch enden: zwei Abbruchfristen
nacheinander beim Herunterfahren, eine Frontmatter-Regel, die an Leerraum scheiterte, und ein
Schreibweg ohne Versionsprüfung.

| Was | Wie |
|---|---|
| Herunterfahren | Takte und Listener teilen sich eine Abbruchfrist von 5 s; eine abgebrochene Aufgabe, die die Frist überdauert, behält eine starke Referenz |
| Gnadenfrist | Compose `stop_grace_period` 75 s (bisher 70), Kubernetes `terminationGracePeriodSeconds` 85 (bisher 80) — 2 s für das Schließen der Verbindungen; die Wächter rechnen mit `ABBRUCH_FRIST_S` |
| Frontmatter | `--- ` mit Leerraum am Ende schließt den Kopf; ein Kopf `false`/`0`/`[]` ist im strengen Modus ein Fehler statt still `{}` |
| Datenschutz-Schalter | `PUT /api/config/privacy` schreibt nur auf den eben gelesenen Stand — sonst 409 statt einer verlorenen fremden Änderung |
| Tests | Sitzungssperre bei doppeltem Abbruch; der Agent-Test „Schreiben trotz Frist“ hängt nicht mehr an der Uhr |

## Was sich im Betrieb ändert

| Was | Muss | Kann |
|---|---|---|
| Image | neu bauen; keine Migration | |
| Compose | `stop_grace_period: 75s` übernehmen (steht in `deploy/compose.prod.yml`) | |
| Kubernetes | `terminationGracePeriodSeconds: 85` übernehmen (`deploy/helm/values.example.yaml`) | |
